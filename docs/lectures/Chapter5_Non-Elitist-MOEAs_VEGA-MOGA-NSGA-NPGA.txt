FOUNDATIONS
Quick Refresher: GA Vocabulary Used Today
Foundations 3
Population / Individual
A population is the set of candidate solutions kept each generation. Each 
individual is one solution, encoded as a chromosome — a vector of genes. Every 
example today uses REAL-VALUED genes (the decision variable's actual number, 
e.g. x = 33.3), not binary strings.
Generation
One full cycle: evaluate objectives → select parents → crossover → mutate → 
new population. "Iteration" and "generation" are used interchangeably in this 
lecture.
Crossover (rate pc) & Mutation (rate pm)
Crossover combines two parents' genes into a child. MOGA, NSGA and the case 
study use arithmetic crossover: child = average(parent1, parent2), rounded if the 
variable must be an integer (e.g. a turbine count). VEGA's example uses copy-
based crossover instead (a child copies one parent unchanged) — you'll see why 
that distinction matters when you get there. Mutation randomly perturbs a gene 
to keep exploring.
Selection operators (differ by algorithm!)
Truncation — keep the top-k by fitness (VEGA). Roulette-wheel / proportional —
probability of being chosen is proportional to fitness (MOGA, NSGA). Tournament 
— compare a small random group and keep the best (NPGA).
Notation used throughout: N = population size,  k = number of objectives,  n = number of decision variables (see the Dimensionality slide shortly).

Recap: Pareto Dominance & Optimality
Foundations 4
● A solution x dominates y (written x ≻ y) if x is no worse than y in every objective, 
and strictly better in at least one.
● For a minimization problem with objectives f1 … fk: x ≻ y  ⇔ fm(x) ≤ fm(y) for 
all m,  and  fm(x) < fm(y) for at least one m.
● For a MAXIMIZATION objective, flip the inequality: higher is better, so use fm(x) 
≥ fm(y) (strict > for at least one). Several examples ahead (NSGA, NPGA) 
maximize directly — just apply the right direction per objective; mixing 
‘minimize cost’ and ‘maximize reliability’ in the same problem is completely 
normal.
● A solution is Pareto-optimal if no other feasible solution dominates it.
● The set of all Pareto-optimal solutions in objective space is the Pareto front.
● MOEAs approximate this front with a population, using dominance instead of a 
single scalar fitness.
Dominance test
Minimize:  fm(x) ≤ fm(y)      Maximize:  fm(x) ≥ fm(y)

FOUNDATIONS
Elitism vs. Non-Elitism: Definitions
Foundations 5
Elitism
● Guarantees that the best solutions found so far survive into the next 
generation, usually via an external archive or by mixing parents with 
offspring before selection.
● Never loses a non-dominated solution once found.
● Basis of modern methods: NSGA-II, SPEA2, PESA-II, MOEA/D.
Non-Elitism (this lecture)
● Selection acts only on the current generation's population — nothing is 
archived.
● A good, non-dominated solution can vanish forever if genetic drift, 
crossover, or mutation removes it.
● Historically first (1985–1994): VEGA, MOGA, NSGA, NPGA — the subject 
of today's lecture.
Key consequence:  non-elitist methods can converge, then regress — the Pareto approximation is not monotonically improving generation to generation.

Diversity Preservation: The Sharing Function
Foundations 6
● MOGA, NSGA and NPGA all fight genetic drift the same way: fitness sharing 
(niching) — solutions clustered near others are penalized so the population spreads 
out.
● dij is the distance between individuals i and j in (normalized) objective space.
● Before computing dij, each objective is normalized to [0,1] with min–max scaling, so 
objectives on different scales (dollars vs. a 0–1 reliability score) contribute equally to 
distance.
● σshare is the niche radius — a tunable hyperparameter (its value differs across the 
worked examples ahead purely to illustrate its effect; a common heuristic is roughly 
the typical spacing between neighboring solutions).
Normalize first
f'm(x) = (fm(x) − fm_min) / (fm_max − fm_min)
Sharing function
sh(dij) = 1 − (dij / σshare)²   if dij < σshare, else 0
Niche count:  NC(i) = Σj sh(dij)
Shared fitness:  Fshared(i) = F(i) / NC(i)

Decision Variables: From 1 to 2 to n Dimensions
Foundations 7
A candidate solution is a decision vector  x = (x1, x2, …, xn) ∈ ℝⁿ
Every objective still takes the WHOLE vector:  f1(x), f2(x), …, fk(x)  — n never changes k, the number of objectives.
Aspect n = 1 (scalar) n = 2 (vector) n = general (n genes)
Chromosome x = x1  (one gene) x = (x1, x2)  (two genes) x = (x1, …, xn)  (n genes)
Used in this lecture VEGA, MOGA, NPGA (e.g. wingspan x) NSGA (x1 = agriculture, x2 = industry) Case study extension (n fields, n warehouses, …)
Crossover child = average(parent1, parent2) — one common 
choice (VEGA's example ahead instead copies a 
parent unchanged, since blending isn't the only 
option)
single-point: swap x1 or x2 between parents, or 
average both genes
pick cut point c ∈ {1..n−1}: genes 1..c from parent A, 
c+1..n from parent B (or mutate each gene 
independently — “uniform crossover”)
Mutation perturb the one gene perturb x1 and/or x2, each with probability pm perturb EACH of the n genes independently, each 
with probability pm
Decision-space distance d(xi,xj) = |xi − xj| d(xi,xj) = √[(xi1−xj1)²+(xi2−xj2)²] d(xi,xj) = √[Σ l=1..n (xi,l − xj,l)²]   (Euclidean norm)
Don't confuse the two dimensions in this lecture: n = number of DECISION variables (the chromosome length, varies by problem)vs. k = number of OBJECTIVES (always 2 in our examples). 
The sharing distance dij used in MOGA/NSGA/NPGA is computed in k-dimensional OBJECTIVE space — it stays 2-D even when n grows.

VEGA · CONCEPT
VEGA: Vector Evaluated Genetic Algorithm
VEGA · Concept 8
Full form: Vector Evaluated Genetic Algorithm     Proposed by: Schaffer (1985)
Core Idea
Split the mating pool into k equal sub-populations (k = number of objectives). 
Each sub-population is selected using ONE objective only, then all sub-
populations are shuffled back together before crossover and mutation.
Algorithm Steps
1.  Evaluate every objective f1…fk for each individual
2.  Split the population into k equal sub-populations
3.  Select sub-population m using objective fm only (proportional selection)
4.  Shuffle all sub-populations back into one mating pool
5.  Apply crossover and mutation
6.  Repeat until the stopping criterion is met
Selection probability (per sub-population m)
P(i, m) = fm(xi) / Σj fm(xj)
Individual i's share of pool m is proportional to fm(xi).
(Worked examples below use the simpler top-k TRUNCATION 
version of this same idea.)
Advantages
● Simple extension of a standard GA
● Trivial to implement
● Fast — one pass per objective per 
generation
Disadvantages
● Poor diversity — drifts to extremes
● No elitism: best solutions can vanish
● Cannot represent balanced 
compromise solutions
Best used when: teaching MOO basics or quickly locating extreme (single-objective-best) 
solutions.
Avoid when: a diverse, well-spread Pareto front or balanced trade-offs are required.
Complexity: O(kN) per generation   |   Parameters: population size N, pc, pm

VEGA · APPLIED PROBLEM
Real-Life Problem: Aircraft Wing Design
VEGA · Applied Problem 9
Scenario
An aerospace engineer is sizing the wing of a regional aircraft. A longer wingspan changes two 
things at once: it lowers fuel burn per flight, but it also allows a wider cabin cross-section and 
hence more passenger capacity. The engineer needs a spread of good wingspan choices, not 
just one number.
Decision Variable
x = wingspan, restricted to the practical range 10 m ≤ x ≤ 50 m. This is the n = 1 case from the 
Dimensionality slide: a single-gene chromosome.
Objective Functions
f1(x) = 1000 / x        — minimize fuel consumption
f2(x) = x² / 100      — maximize passenger capacity
MOEA Approach
● Split the population: half the mating pool is chosen by f1, half by f2.
● Shuffle the two halves together, then apply crossover + mutation.
● Track whether the population keeps any wingspan values between the two extremes.
Trade-off
Two conflicting goals — improving one worsens the other. 
No single x optimizes both.

MOGA · CONCEPT
MOGA: Multi-Objective Genetic Algorithm
MOGA · Concept 14
Full form: Multi-Objective Genetic Algorithm     Proposed by: Fonseca & Fleming (1993)
Core Idea
Rank each individual by how many other individuals dominate it (not by raw 
objective value), turn rank into fitness, then apply fitness sharing so crowded 
ranks don't collapse onto one point.
Algorithm Steps
1.  Evaluate all objectives for every individual
2.  rank(i) = 1 + (number of individuals that dominate i)
3.  Assign raw fitness F(i) = 1 / rank(i)
4.  Compute pairwise distance dij and apply the sharing function
5.  Divide: Fshared(i) = F(i) / NC(i)
6.  Select, crossover, and mutate using Fshared
Rank-based fitness
F(i) = 1 / rank(i)
Fshared(i) = F(i) / NC(i)   (NC from the sharing formula)
Advantages
● Dominance-based ranking is fairer 
than VEGA's split
● Sharing actively maintains diversity
● Clearly better spread than VEGA
Disadvantages
● Still non-elitist — rank leaders can be 
lost
● Needs the niche radius σshare tuned 
by hand
● Slower per generation than VEGA
Best used when: moderate diversity is needed and you want to teach dominance-rank 
fitness.
Avoid when: very fast convergence is required, or elitism is mandatory.
Complexity: O(kN²) per generation   |   Parameters: niche radius σshare, population size

MOGA · APPLIED PROBLEM
Real-Life Problem: Wind Farm Layout
MOGA · Applied Problem 15
Scenario
A renewable-energy company is deciding how many turbines to install in a new wind farm. 
Adding turbines increases total construction and maintenance cost, but the energy captured 
grows more slowly than linearly (wake losses), giving a genuine sub-linear trade-off curve.
Decision Variable
x = number of turbines, an integer with 5 ≤ x ≤ 20.
Objective Functions
f1(x) = 10x                — minimize total cost
f2(x) = 100·√x            — maximize energy output
MOEA Approach
● Compute dominance rank for every candidate layout.
● Apply fitness sharing across the (mostly rank-1) population.
● Select the least-crowded, highest-fitness layouts to breed.
Trade-off
Two conflicting goals — improving one worsens the other. 
No single x optimizes both.

NSGA · CONCEPT
NSGA: Non-Dominated Sorting Genetic Algorithm (Original)
NSGA · Concept 21
Full form: Non-Dominated Sorting Genetic Algorithm     Proposed by: Srinivas & Deb (1994)
Core Idea
Peel the population into fronts by repeated non-dominated sorting (Front 1 = 
non-dominated, Front 2 = dominated only by Front 1, etc.), give every front a 
big dummy fitness gap, then share fitness within each front.
Algorithm Steps
1.  Sort the population into fronts F1, F2, … by dominance
2.  Assign dummy fitness F(i) = Fmax − (rank(i) − 1)×ΔF
3.  Within EACH front, compute sharing and get Fshared(i) = F(i) / NC(i)
4.  Select, crossover, mutate using Fshared
5.  Re-sort into fronts next generation
Dummy fitness by front
F(i) = Fmax − (rank(i) − 1) × ΔF
Fshared(i) = F(i) / NC(i)   (sharing applied WITHIN a 
front)
Advantages
● Very good diversity via within-front 
sharing
● The non-dominated sorting concept 
is conceptually clean
● Directly inspired NSGA-II
Disadvantages
● O(kN³) sorting cost — very slow for 
large N
● Still non-elitist: front 1 members can 
be lost
● Needs σshare tuned per front
Best used when: teaching the historical roots of non-dominated sorting, or working with 
small populations.
Avoid when: large populations or fast turnaround are needed.
Complexity: O(kN³)   |   Parameters: σshare, population size

NSGA · APPLIED PROBLEM
Real-Life Problem: Water Resource Allocation
NSGA · Applied Problem 22
Scenario
A regional water authority must split a fixed water supply between agriculture and industry. 
Every liter given to one sector is a liter not given to the other, subject to a hard supply cap —
the classic constrained bi-objective allocation problem.
Decision Variable
x1 = water to agriculture, x2 = water to industry, with x1 + x2 ≤ 100 (units: million liters/day). 
This is the n = 2 case from the Dimensionality slide: x = (x1, x2).
Objective Functions
f1 = x1     — maximize agricultural yield
f2 = x2     — maximize industrial output
MOEA Approach
● Sort candidate allocations into non-dominated fronts.
● Share fitness within Front 1 so the sorting doesn't collapse to one allocation.
● Select across fronts, favoring Front 1 with high shared fitness.
Trade-off
Two conflicting goals — improving one worsens the other. 
No single x optimizes both.

NPGA · CONCEPT
NPGA: Niched Pareto Genetic Algorithm
NPGA · Concept 27
Full form: Niched Pareto Genetic Algorithm     Proposed by: Horn, Nafpliotis & Goldberg (1994)
Core Idea
Replace fitness computation entirely with Pareto tournaments: pick 2 
candidates plus a small random comparison set. If dominance decides 
between the 2 candidates, pick the winner; if neither dominates, break the 
tie with niche count (pick the LESS crowded one).
Algorithm Steps
1.  Pick 2 candidates i, j at random — this is the “tournament size”, fixed at 2 
throughout this lecture (a binary tournament)
2.  SEPARATELY pick a comparison set of size t at random (t = 2 in every worked 
example here) — used only to measure crowding, not to compete directly
3.  If i dominates j (against nobody else) → select i; if j dominates i → select j
4.  If neither dominates → compute niche count of i and j against the 
comparison set
5.  Select whichever of i, j has the LOWER niche count (less crowded)
6.  Repeat to fill the mating pool
Niche count against the comparison set
NC(i) = Σ (over comparison set j) sh(dij)
Lower NC(i) wins the tie-break — it is less crowded
Advantages
● No explicit fitness function to 
compute — fast
● Directly uses Pareto dominance
● Simple to implement as a selection 
operator
Disadvantages
● Needs σshare AND comparison-set 
size tuned
● Still non-elitist
● Result quality depends on 
comparison-set size
Best used when: fast selection is the priority and moderate diversity is acceptable.
Avoid when: maximum diversity or guaranteed elitism is required.
Complexity: O(kN²)   |   Parameters: σshare, tournament size, comparison-set size

NPGA · APPLIED PROBLEM
Real-Life Problem: Telecom Network Design
NPGA · Applied Problem 28
Scenario
A telecom operator is choosing a network topology. Cheaper topologies (fewer redundant links) 
cost less to build, but redundancy is what makes a network resilient to failures — cost and 
reliability trade off directly.
Decision Variable
x = network topology choice — a discrete design, not a formula. Unlike the earlier problems, 
there's no closed-form f(x): each candidate topology below (A, B, C, D) is simply given directly by 
its own (cost, reliability) outcome.
Objective Functions
f1 = build cost           — minimize
f2 = reliability score  — maximize
MOEA Approach
● Normalize cost and reliability to a common [0,1] scale before measuring distance.
● Run Pareto tournaments between pairs of candidate topologies.
● Break non-dominated ties using niche count so crowded topologies lose to unique ones.
Trade-off
Two conflicting goals — improving one worsens the other. 
No single x optimizes both.

SYNTHESIS
Why We Need Elitist MOEAs
Synthesis 35
! Loss of best solutions
Every method above can drop a non-dominated solution once 
selection, crossover, or mutation removes it — nothing preserves it.
! Slow, oscillating convergence
With no memory of past good solutions, the approximation quality 
can regress between generations instead of improving 
monotonically.
! Computational cost
NSGA's within-front sharing costs O(kN³) per generation —
prohibitive once N grows past a few hundred.
! Diversity vs. convergence tension
Stronger sharing (small σshare) fights crowding but also fights 
convergence toward the true front — tuning is delicate and problem-
specific.
The fix: Elitist MOEAs — NSGA-II, SPEA2, PESA-II, MOEA/D — merge parents with offspring before selection, so a non-dominated solution, once found, is never lost 
again.

WRAP -UP
Key Takeaways — Non-Elitist MOEAs
Wrap-up 39
VEGA (1985) Simple objective-wise split. Fast, but converges hard to the extremes — the balanced middle of the trade-off is lost.
MOGA (1993) Dominance-rank fitness plus sharing. A genuine step up in diversity, at O(kN²) cost.
NSGA (1994) Explicit non-dominated fronts plus within-front sharing. Best diversity of the four, but O(kN³) is expensive.
NPGA (1994) Pareto tournaments with niche-count tie-breaks. Fast selection, good diversity, no explicit fitness needed.
All four are non-elitist — the best solutions found can still be lost. Next lecture: Elitist MOEAs (NSGA-II, NSGA-III, SPEA2, PESA-II, MOEA/D).
