FOUNDATIONAL CONCEPT
Elitism: Preserving the Best Solutions
DEFINITION
Elitism means keeping the best solutions from the previous generation so they are never lost while evolving the population.
WHY ELITISM?
• Prevents loss of good solutions
• Speeds up convergence
• Improves diversity
HOW DOES IT WORK?
• Combine parent and offspring populations
• Select the best solutions for the next generation
EXAMPLES:  NSGA-II, NSGA-III, SPEA2, PESA-II, MOEA/D
HISTORICAL CONTEXT:  Introduced in the late 1990s to overcome the limitations of earlier non-elitist MOEAs.

NSGA-II: Non-Dominated Sorting GA II
FULL FORM
Non-Dominated Sorting Genetic Algorithm II
PROPOSED BY
Deb, Pratap, Agarwal & Meyarivan (2002)  [1]
CATEGORY
Elitist MOEA
CORE IDEA
Fast non-dominated sorting + crowding distance + elitism. Solutions are ranked into Pareto fronts, and a crowding distance measure preserves diversity along 
each front.
KEY FORMULAS
Non-Dom. Sort np = 0 → Front 1;  for each q ∈ Sp, decrement nq;  nq = 0 → next frontComplexity: O(kN²)  vs.  O(kN³) for classic NSGA
Crowding Dist. d_i = Σ(m=1→M)  [ f_m(i+1) − f_m(i−1) ] / [ f_m^max − f_m^min ]Boundary solutions: d = ∞
Crowded Comparison Prefer lower rank (better front); if tied, prefer higher crowding distance (better diversity)
VISUAL FLOW
Parents + Offspring → Non-Dominated Sort → Crowding Distance → Select Best N

NSGA-II
Step-by-Step Algorithm
1 Initialize population P₀ randomly
2 Evaluate all objectives for every individual
3
Fast Non-Dominated Sorting: rank solutions into fronts F₁, F₂, …
4 Crowding Distance: compute for each solution in a front
5
Selection: crowded-comparison tournament based on rank + crowding distance
6 Crossover and Mutation: create offspring population Qⱼ
7 Combine: Rⱼ = Pⱼ ∪ Qⱼ (parents + offspring)
8 Elitist Selection: sort Rⱼ by front & crowding distance; select the best N 
solutions
9 Repeat steps 3–8 until stopping criteria are met

NSGA-II
Advantages, Disadvantages & When to Use
✅
  Advantages
• Fast: O(kN²) vs O(kN³) for classic NSGA
• Elitism preserves the best solutions found
• Crowding distance keeps solutions diverse
• No extra diversity parameter (like niche radius) needed
❌
  Disadvantages
• Crowding distance struggles beyond ~3 objectives
• Diversity mechanism is less precise than an archive-based method
• Convergence can stall on complex, deceptive landscapes
✓  Best Used When
• Problems with 2 (or up to ~3) objectives
• A fast, easy-to-implement elitist MOEA is needed
• General-purpose benchmark or teaching use
⚠
  Avoid When
• Many-objective problems (4+ objectives) — prefer NSGA-III
• An explicit solution archive is required — prefer SPEA2
PARAMETERS:  Population size N, crossover prob. pᴄ, mutation prob. pⱼ     |     COMPLEXITY:  O(kN²) per generation (k = objectives, N = population size)

NSGA-II — WORKED NUMERICAL (ITERATION 1)
Real-Life Problem: Bridge Design
Scenario
A civil engineer designs a bridge beam. Decision variable x = beam thickness (1–5 m). Objectives: minimize cost f₁(x) = x²  and  maximize load capacity f₂(x) = 100 − (x−3)² 
(capacity peaks at x = 3 m).
Initial Population & Evaluation
• x = [1, 2, 3, 4]
• x=1: f₁=1, f₂=96
• x=2: f₁=4, f₂=99
• x=3: f₁=9, f₂=100
• x=4: f₁=16, f₂=99
Step 1: Non-Dominated Sorting
• Check x=4 vs x=2: x=2 has lower cost (4<16) AND 
equal/higher capacity (99=99) → x=2 dominates 
x=4
• Check x=4 vs x=3: x=3 has lower cost (9<16) AND 
higher capacity (100>99) → x=3 dominates x=4
• x=1, x=2, x=3 are mutually non-dominated (each 
trades cost for capacity)
Step 2: Crowding Distance
• Result: Front 1 = {1, 2, 3},  Front 2 = {4}  (x=4 is the 
dominated point, not x=1!)
• Front 1 boundaries x=1 and x=3 (sorted by cost) → 
d = ∞
• x=2 (interior):  d = |9−1|/(9−1) + 
|100−96|/(100−96) = 1 + 1 = 2

Bridge Design — Selection, Crossover & Convergence
Selection
• Tournament favors the two boundary solutions (d =

ALGORITHM 2 OF 7 — ELITIST, MANY-OBJECTIVE MOEA
NSGA-III: Non-Dominated Sorting GA III
FULL FORM
Non-Dominated Sorting Genetic Algorithm III
PROPOSED BY
Deb & Jain (2014)  [2]
CATEGORY
Elitist, Many-Objective MOEA
CORE IDEA
Extends NSGA-II with reference points spread on a hyperplane to maintain diversity when there are three or more objectives, where crowding distance alone 
becomes unreliable.
KEY FORMULAS
Reference Pts. H = C(M + p − 1, p)(M = objectives, p = divisions per objective axis)
Association Each solution → its nearest reference line/point (perpendicular distance)
Non-dominated sorting itself is identical to NSGA-II; the diversity mechanism is what changes.
VISUAL FLOW
Reference Points → Non-Dominated Sort → Associate to Niche → Fill Each Niche

NSGA-III
Step-by-Step Algorithm
1
Generate reference points, uniformly distributed on a normalized hyperplane
2
Perform non-dominated sorting (identical procedure to NSGA-II)
3 Normalize objectives and compute perpendicular distance of each solution to 
every reference line
4
Niche Preservation: associate each solution with its nearest reference point
5 Fill each niche by selecting the solutions closest to under-represented reference 
points
6 Repeat until the next generation of size N is filled

ALGORITHM 3 OF 7 — ELITIST, ARCHIVE-BASED MOEA
SPEA2: Strength Pareto Evolutionary Algorithm 2
FULL FORM
Strength Pareto Evolutionary Algorithm 2
PROPOSED BY
Zitzler, Laumanns & Thiele (2001)  [3]
CATEGORY
Elitist MOEA
CORE IDEA
Maintains an external archive of non-dominated solutions. Fitness combines a dominance-based “strength” term with a density (nearest-neighbor) term for 
fine-grained diversity.
KEY FORMULAS
Strength S(i) = | { j : i ≻ j } |   (how many solutions i dominates)
Raw Fitness R(i) = Σ (j ≺ i)  S(j)   (sum of strengths of i's dominators)
Density D(i) = 1 / (σᵢᵏ + 2)   (σᵢᵏ = distance to k-th nearest neighbor)
Final Fitness F(i) = R(i) + D(i)   (lower is better)
VISUAL FLOW
Compute Strength → Raw Fitness → Density → Update Archive
SPEA2 CH. 5 · ELITIST MOEAs

PAGE 21
3
SPEA2
Step-by-Step Algorithm
1 Initialize population and an empty external archive
2
Compute Strength S(i) for every individual in population + archive
3
Compute Raw Fitness R(i) by summing strengths of dominators
4 Compute Density D(i) using k-th nearest-neighbor distance
5 Combine: Final Fitness F(i) = R(i) + D(i)
6
Environmental Selection: copy all non-dominated individuals (F < 1) into the 
archive; truncate by density if archive overflows, or fill with best-ranked 
dominated solutions if it is under-full
7
Apply tournament selection, crossover and mutation to generate offspring
8 Repeat until stopping criteria are met

Advantages, Disadvantages & When to Use
✅
  Advantages
• External archive preserves elite non-dominated solutions
• Strength + density fitness gives excellent diversity
• Fine-grained density estimation (k-th nearest neighbor) is very accurate
❌
  Disadvantages

⚠
  Avoid When

FULL FORM
Pareto Envelope-Based Selection Algorithm II
PROPOSED BY
Corne, Jerram, Knowles & Oates (2001)  [4]
CATEGORY
Elitist MOEA
CORE IDEA
Diversity is maintained with a hyper-grid over objective space instead of crowding distance or an archive-density metric — solutions in less-crowded grid cells 
are preferred.
KEY FORMULAS
Grid Squeeze squeeze(cell) = number of solutions currently occupying that hyperbox
Selection Rule Prefer individuals from cells with the lowest squeeze factor (least crowded)
VISUAL FLOW
Build Hyper-Grid → Place Solutions → Count Per Cell → Favor Sparse Cells

Preferentially select parents/survivors from less-crowded cells

MOEA/D: MOEA Based on Decomposition
FULL FORM
Multi-Objective Evolutionary Algorithm Based on Decomposition
PROPOSED BY
Zhang & Li (2007)  [5]
CATEGORY
Elitist MOEA
CORE IDEA
Decomposes the multiobjective problem into N scalar single-objective subproblems using weight vectors, and optimizes them together, sharing information 
among neighboring subproblems.
KEY FORMULAS
Weighted Sum g(x|λ) = Σ(i=1→k) λᵢ fᵢ(x)
Tchebycheff g(x|λ) = maxᵢ [ λᵢ · | fᵢ(x) − zᵢ* | ]     (z* = ideal point)
Boundary Intersection PBI: g(x|λ) = d₁ + θ·d₂   (d₁ = projection onto λ, d₂ = perpendicular distance)A third decomposition option, alongside Weighted Sum & Tchebycheff
Neighborhood B(i) = the T weight vectors closest to λᵢ (defines who i shares information with)
VISUAL FLOW
Weight Vectors → Decompose to Subproblems → Neighbor Mating → Update Solutions

MOEA/D
Step-by-Step Algorithm
1
Initialize N weight vectors λ₁, …, λⱼ spread across objective space
2
Compute neighborhoods B(i): the T closest weight vectors to each λᵢ
3 Initialize population x₁, …, xⱼ and the ideal point z*
4
For each subproblem i: select mating parents from its neighborhood B(i)
5
Generate an offspring via crossover/mutation on the selected parents
6 Update the ideal point z* if the offspring improves it
7
Update neighboring solutions if the offspring improves their subproblem value
8 Update the external archive of non-dominated solutions; repeat until 
convergence

Summary & Key Takeaways
Elitism Matters
Merging parents + offspring and keeping only the best solutions prevents loss of 
good genes and speeds convergence.
Diversity Mechanisms Differ
Crowding distance (NSGA-II), reference points (NSGA-III), density/archive 
(SPEA2), grids (PESA-II), and weight vectors (MOEA/D) all solve diversity 
differently.
Decomposition Scales Well
MOEA/D and its DE/ACO variants turn a hard multiobjective problem into many 
simple scalar subproblems — ideal for large or many-objective problems.
Match Algorithm to Problem
2 objectives → NSGA-II. 3+ objectives → NSGA-III / MOEA/D. Need an archive 
→ SPEA2. Need speed → PESA-II. Continuous → MOEA/D-DE. Discrete → 
MOEA/D-ACO.
