Notation Guide: Same Symbol, Different Meaning
Several standard symbols get reused across the literature for unrelated quantities. Each reuse is flagged again on its own slide, but here they are collected in one place.
α (alpha) RVEA: fixed penalty-strength constant (≈2) in the APD formula  ·  GradNorm: fixed asymmetry hyperparameter  ·  MGDA: α*, a SOLVED optimal mixing weight (an output, not an input) — three unrelated constants, same letter.
ε (epsilon) IBEA: names the 'ε-indicator' I(a,b)=max(aᵢ−bᵢ)  ·  Lexicographic: a small tolerance when holding a higher-priority optimum (f1(x)≥f1*−ε)  ·  R-NSGA-II: the ε-clearing radius that preserves a spread of solutions.
d⁺, d⁻ Goal Programming: DEVIATIONAL VARIABLES — part of the decision problem (over/under-achievement of a target)  ·  TOPSIS: DISTANCES to the ideal/anti-ideal point — a computed output used only for ranking.
r  vs.  v SMS-EMOA / HypE: r = one dominated reference POINT in objective space  ·  RVEA: v₁..v_H = reference VECTORS (directions)  ·  VIKOR: v = a scalar trade-off WEIGHT in [0,1] — three unrelated things.
C NSGA-III: C(k+p−1,p), the binomial 'choose' function → a reference-point COUNT  ·  TOPSIS: Cᵢ, the closeness coefficient → a per-alternative score in [0,1].
g1, g2 / target MGDA: g1,g2 are gradient VECTORS (:=∇f1,∇f2)  ·  GradNorm: g1,g2 are fixed gradient-norm MAGNITUDES (scalars); its targetᵢ is recomputed every step, unlike Goal Programming's fixed target Tᵢ.
k  (vs. classical 'M') This deck standardizes on k = number of objectives everywhere. The original NSGA-III paper (and several textbooks) uses M for the same quantity — same meaning, different letter.

Why NSGA-II Isn't Enough at 3+ Objectives
The many-objective challenge (k ≥ 3)
• Diversity loss — as k grows, almost every solution in a random population 
becomes mutually non-dominated, so Pareto rank alone can no longer tell 
good from mediocre.
• Selection pressure collapses — crowding distance (NSGA-II's tiebreaker) was 
designed for 2–3 objectives; in 5+ dimensions it no longer reliably spreads 
solutions.
• Fix #1 — Decomposition: pre-place structured reference points/vectors across 
the objective space and let each one 'claim' its nearest solution (NSGA-III, 
RVEA).
• Fix #2 — Indicators: replace Pareto rank with a scalar quality indicator (ε-
indicator, hypervolume) that remains discriminating at any k (IBEA, SMS-EMOA, 
HypE).
At k = 3 objectives, a population of 100 random points is 
typically
70–95% mutually non-dominated.
This deck's running example
Drone design (3 obj.): wingspan & motor power → weight, cost, 
flight time.
Laptop design (2 obj.): weight vs. price, for indicator/preference 
methods.
Supplier selection (MCDA): cost, quality, delivery time.
Production planning (LP): profit & output targets.
Multi-task model training: two loss functions sharing parameters.

NSGA-III: Concept & Generalized Steps
Full form: Non-Dominated Sorting Genetic Algorithm III
Proposed by: Deb & Jain (2014)
Core idea
• Replace crowding distance with structured reference points on a 
normalized hyperplane, so selection pressure survives even when almost 
every solution is mutually non-dominated (k ≥ 3).
Pros / Cons / When to use
•
 Scales cleanly to many objectives via structured reference points.
•
 Needs the reference-point count decided upfront; more moving parts than 
NSGA-II.
• Best used when: 5+ objectives.
• Parameters: Divisions per axis p → H = C(k+p-1, p) reference points.
Generalized steps (any n variables, k objectives)
1.  For k objectives, generate H = C(k+p-1, p) structured reference points using p divisions per 
axis (H grows combinatorially with k, not with n).
2.  Initialize a population of N ≈ H individuals, each an n-dimensional decision vector 
x=(x1,…,xn); evaluate all k objectives.
3.  Merge parents + offspring; non-dominated sort into fronts F1, F2, ….
4.  Compute the ideal point (per-objective min) and an estimated nadir; normalize every 
objective vector to [0,1]^k. (Teaching simplification: we estimate nadir as the translated per-
objective max; the original paper instead fits a hyperplane through extreme points for a more 
robust estimate.)
5.  Associate each individual with its nearest reference line by perpendicular distance in 
normalized k-D space; tally niche counts.
6.  Fill next generation front-by-front; in the last partially-accepted front, prefer individuals 
whose reference point currently has the fewest selected members.
Dimension handling: n (variable count) affects only evaluation cost, not selection; k (objective 
count) drives H and every normalization step.

RVEA: Concept & Generalized Steps
Full form: Reference Vector Guided Evolutionary Algorithm
Proposed by: Cheng, Olhofer & Jin (2016)
Core idea
• Use unit reference vectors plus an Angle-Penalized Distance (APD) that 
grows with generation progress — exploration early, convergence pressure 
late.
Pros / Cons / When to use
•
 Scales to many objectives; adapts vectors to the current objective ranges.
•
 Vector generation/adaptation adds complexity; sector-exclusive selection 
can retain a dominated point (see result table).
• Best used when: 5+ objectives.
• Parameters: Number of reference vectors H; penalty exponent α; max 
generations tmax.
Generalized steps (any n variables, k objectives)
1.  Generate unit reference vectors v1..vH over the k-D simplex (identical construction to 
NSGA-III's points, then unit-normalized).
2.  Normalize objectives every generation via ideal/nadir estimates, so raw units never bias 
the angle calculation, for any n or k.
3.  Assign each individual to the reference vector with the smallest angle θ to its normalized, 
ideal-shifted objective vector.
4.  Compute APD(x) = d(x)·[1 + α·(t/tmax)·θ(x)/γmin], where d = distance from ideal and γmin 
= smallest angle between neighbouring vectors. (α here is a FIXED penalty-strength constant, 
typically 2 — unrelated to GradNorm's asymmetry α or MGDA's solved α*; see the Notation 
Guide.)
5.  Within each vector's sector, keep only the individual with the smallest APD (elitist, one 
survivor per sector).
6.  Periodically adapt the reference vectors to the population's current objective ranges; 
repeat.
Dimension handling: Sector count H scales with k exactly as in NSGA-III; n only affects how 
offspring are generated inside each sector.

IBEA: Concept & Generalized Steps
Full form: Indicator-Based Evolutionary Algorithm
Proposed by: Zitzler & Künzli (2004)
Core idea
• Fitness comes directly from a binary quality indicator (ε-indicator) 
measured against every other solution — selection optimizes indicator 
quality, not Pareto rank.
Pros / Cons / When to use
•
 Directly optimizes a chosen indicator; good convergence.
•
 Indicator computation cost; κ must be tuned; sensitive to un-normalized 
objective scales (see result table).
• Best used when: Quality of the final front (by a chosen indicator) is the priority.
• Parameters: κ (fitness scaling), indicator type.
Generalized steps (any n variables, k objectives)
1.  Choose an indicator I(a,b); the additive ε-indicator I(a,b)=maxᵢ(aᵢ−bᵢ) works for any k. 
Reading it: I(a,b) large & positive ⇒ a is much worse than b in at least one objective; I(a,b) ≤ 0 
⇒ a already weakly dominates b.
2.  Evaluate the k-D objective vector of each of the N individuals (I is always computed in 
objective space, independent of n).
3.  Fitness F(i) = Σⱼ≠ᵢ −exp(−I(i,j)/κ); scale κ to the indicator's typical magnitude range in THIS 
problem.
4.  Environmental selection: repeatedly delete the individual with the largest (worst) F, RE-
COMPUTING all remaining fitnesses after each deletion.
5.  Generate offspring from survivors; repeat.
Dimension handling: κ must be re-tuned whenever objective units/scales change — an un-
normalized scale gap between objectives biases which solutions look 'worst' (see the 
verification note on this module's result slide).

SMS-EMOA: Concept & Generalized Steps
Full form: S-Metric Selection Evolutionary Multi-Objective Algorithm
Proposed by: Beume, Naujoks & Emmerich (2007)
Core idea
• Steady-state (μ+1): create exactly one offspring per iteration; use each 
solution's hypervolume CONTRIBUTION to decide who is removed, directly 
optimizing the metric that matters most.
Pros / Cons / When to use
•
 Hypervolume-based; excellent convergence AND diversity in one criterion.
•
 Exact hypervolume is expensive to compute as k grows.
• Best used when: 2–3 objectives.
• Parameters: Population size μ; reference point r.
Generalized steps (any n variables, k objectives)
1.  Fix a reference point r, component-wise worse than every feasible k-D objective vector.
2.  Initialize a population of size μ; evaluate k objectives (independent of the n variables that 
produced them).
3.  Generate ONE offspring via variation; add it to the population (size μ+1).
4.  Non-dominated sort the μ+1 individuals; identify the worst front.
5.  If the worst front has >1 member, delete the one with the smallest hypervolume 
contribution ΔHV = HV(P) − HV(P∖{i}) restricted to that front; otherwise delete its sole 
member.
6.  Repeat until the stopping criterion is met.
Dimension handling: Exact hypervolume is tractable at k=2–3 (used here); its cost grows 
exponentially with k — this is exactly why HypE's Monte-Carlo estimate exists for many-
objective problems.

HypE: Concept & Generalized Steps
Full form: Hypervolume Estimation Algorithm
Proposed by: Bader & Zitzler (2011)
Core idea
• Exact hypervolume is too expensive for many objectives, so estimate each 
solution's contribution via Monte-Carlo sampling inside a bounding box, 
then remove the lowest-estimate solution each round.
Pros / Cons / When to use
•
 Scales to many objectives via sampling; controllable accuracy/cost trade-
off.
•
 Estimation error from finite sampling; needs enough samples S.
• Best used when: Many objectives (k≥4) where exact hypervolume (SMS-EMOA) 
is too slow.
• Parameters: Number of Monte-Carlo samples S.
Generalized steps (any n variables, k objectives)
1.  Define a bounding box between the per-objective ideal point and a dominated reference 
point r; its k-D volume caps achievable hypervolume for any k.
2.  Draw S random sample points uniformly inside the box (S is independent of n; scales only 
with desired accuracy and k).
3.  For every sample, find which population members dominate it, and split that sample's 
share of the box volume equally among its dominators.
4.  Sum each individual's accumulated share across all S samples → its estimated HypE 
fitness/contribution.
5.  Environmental selection: repeatedly remove the lowest-estimate individual, RE-
ESTIMATING after each removal, until population = target size.
Dimension handling: The exactness of SMS-EMOA's hypervolume is traded for a controllable 
sampling error that stays roughly constant as k grows — this is why HypE, unlike SMS-EMOA, is 
recommended for k≥4.

R-NSGA-II: Concept & Generalized Steps
Full form: Reference Point-Based NSGA-II
Proposed by: Deb, Sundar, Bhaskara & Chaudhuri (2006)
The 'R' in R-NSGA-II stands for Reference (point) — unrelated to VIKOR's R (individual regret), covered later in this deck.
Core idea
• The decision-maker (DM) supplies a reference point describing a desired 
trade-off; solutions are ranked by normalized distance to it, with an ε-
clearing rule that preserves a SPREAD near the preference rather than 
collapsing to one point.
Pros / Cons / When to use
•
 Incorporates DM preference directly; focuses search where it matters.
•
 Needs a reference point and ongoing DM involvement; ε must be tuned.
• Best used when: The decision-maker already has a preferred trade-off region.
• Parameters: Reference point(s); clearing radius ε.
Generalized steps (any n variables, k objectives)
1.  DM specifies g reference points in objective space (g=1 here); works for any k (just a k-D 
point) and any n.
2.  Min–max normalize the population's objectives, so distance isn't dominated by whichever 
objective has the largest raw range.
3.  Compute Euclidean distance dᵢ from each normalized solution to the normalized reference 
point.
4.  Sort ascending by dᵢ; accept a solution only if it is ≥ ε away (normalized space) from every 
already-accepted solution (ε-clearing preserves spread).
5.  If clearing leaves fewer than the target count, backfill by pure distance order; repeat next 
generation.
Dimension handling: ε is a single scalar regardless of k, but should shrink as k grows, since 
normalized-space volume grows with dimension (curse of dimensionality on the clearing 
radius).

Goal Programming: Concept & Generalized Steps
Full form: Goal Programming
Proposed by: Charnes & Cooper (1961)
Core idea
• Convert each objective into a GOAL with a target Tᵢ, then minimize the 
(weighted) sum of undesired deviations from those targets — satisficing 
rather than optimizing.
Pros / Cons / When to use
•
 Intuitive target-setting; handles multiple, even conflicting, goals in one LP .
•
 Needs targets to be specified; can be infeasible if targets are unreachable 
together.
• Best used when: Clear, DM-supplied targets exist for each objective.
• Parameters: Targets Tᵢ; deviation weights.
Generalized steps (any n variables, k objectives)
1.  For k goals, introduce target Tᵢ and deviational variables dᵢ⁻, dᵢ⁺ ≥ 0 with fᵢ(x) + dᵢ⁻ − dᵢ⁺ = Tᵢ 
(works for any n inside fᵢ(x), and any k).
2.  Decide which deviation is undesirable per goal (e.g. dᵢ⁻ if the goal is 'at least Tᵢ') and 
penalize only those in the objective.
3.  Add the original hard constraints (resource limits, etc.) unchanged.
4.  Solve the resulting single-objective LP by simplex / any LP method — Goal Programming IS 
linear programming once goals become equality constraints.
5.  Read off deviations: 0 = goal exactly-or-over-achieved; a positive undesired deviation flags 
a goal that could not be fully met.
Dimension handling: Adds exactly 2k new variables (one dᵢ⁻,dᵢ⁺ pair per goal) regardless of n; 
the problem stays an LP as long as every fᵢ(x) is linear in x.

Lexicographic Method: Concept & Generalized Steps
Full form: Lexicographic Method
Proposed by: Classical OR method
Core idea
• Rank objectives strictly by DM-assigned priority; optimize the top-priority 
objective alone, then optimize the next while holding the previous 
optimum fixed — no weights, ever.
Pros / Cons / When to use
•
 Simple once priorities are clear; no weight elicitation needed.
•
 Requires a STRICT ranking (no ties); gives no explicit trade-off between 
objectives.
• Best used when: Objectives have a clear, non-negotiable hierarchy of 
importance.
• Parameters: Objective ranking (priority order).
Generalized steps (any n variables, k objectives)
1.  Rank the k objectives strictly 1..k (if the DM can't rank two strictly, merge them via Goal 
Programming instead).
2.  Optimize the priority-1 objective alone, over all n decision variables, subject to the original 
constraints only → obtain f1*.
3.  Add the constraint f1(x) = f1* (or ≥ f1*−ε) and optimize the priority-2 objective subject to 
this plus the original constraints.
4.  Repeat, adding one 'hold the previous optimum' constraint per stage, until all k objectives 
are processed.
Dimension handling: Each stage is a full n-variable optimization; the number of sequential 
SOLVES equals k, not n — the method scales well in variables but requires k solves in sequence.

TOPSIS: Concept & Generalized Steps
Full form: Technique for Order of Preference by Similarity to Ideal Solution
Proposed by: Hwang & Yoon (1981)
Core idea
• Rank a GIVEN discrete set of alternatives by how close each is to an ideal 
point and how far from an anti-ideal point, combined into one closeness 
coefficient.
Pros / Cons / When to use
•
 Produces a single ranked list; intuitive geometric idea.
•
 Needs weights; sensitive to normalization AND to weight choice (see result 
table).
• Best used when: Ranking a small, already-generated set of Pareto-optimal 
alternatives.
• Parameters: Criteria weights wⱼ (Σwⱼ=1).
Generalized steps (any n variables, k objectives)
1.  Build the m×k decision matrix from m already-generated alternatives (TOPSIS ranks a 
GIVEN set — it does not search over decision variables itself).
2.  Vector-normalize each column: rᵢⱼ = xᵢⱼ / √(Σxᵢⱼ²).
3.  Apply DM weights wⱼ → weighted matrix vᵢⱼ = wⱼ·rᵢⱼ.
4.  Determine ideal A⁺ (best per column, respecting min/max direction) and anti-ideal A⁻ 
(worst per column).
5.  Compute Euclidean distances dᵢ⁺, dᵢ⁻ to A⁺ and A⁻ (these are DISTANCES — a different 
meaning from Goal Programming's dᵢ⁺,dᵢ⁻ deviational VARIABLES seen earlier); closeness Cᵢ = 
dᵢ⁻/(dᵢ⁺+dᵢ⁻) (this Cᵢ is a per-alternative score, unrelated to NSGA-III's C(k+p−1,p) 
combinatorial 'choose' function); rank by Cᵢ descending.
Dimension handling: Cost scales as O(m·k) — linear in both alternatives m and criteria k; 
independent of whatever n produced the alternatives.

VIKOR: Concept & Generalized Steps
Full form: VIseKriterijumska Optimizacija I Kompromisno Resenje
Proposed by: Opricovic (1998)
Core idea
• Rank alternatives by a compromise index Q that blends GROUP utility 
(average regret, S) with INDIVIDUAL worst-case regret (R), via a tunable 
trade-off parameter v.
Pros / Cons / When to use
•
 Explicitly balances average performance vs. worst-case regret; can propose 
a compromise SET, not just a winner.
•
 Needs v chosen; more computation than TOPSIS.
• Best used when: A compromise solution (not necessarily the 'closest to ideal') 
is wanted.
• Parameters: Trade-off weight v ∈[0,1] (0.5 = common default).
Generalized steps (any n variables, k objectives)
1.  Use the same m×k decision matrix and weights wⱼ as TOPSIS.
2.  Compute best fⱼ* and worst fⱼ⁻ per criterion (respecting min/max direction).
3.  Per alternative: group utility Sᵢ=Σⱼwⱼ(fⱼ*−fᵢⱼ)/(fⱼ*−fⱼ⁻) and individual regret Rᵢ=maxⱼ
wⱼ(fⱼ*−fᵢⱼ)/(fⱼ*−fⱼ⁻).
4.  Compromise index Qᵢ = v(Sᵢ−S*)/(S⁻−S*) + (1−v)(Rᵢ−R*)/(R⁻−R*). (This v is a scalar trade-off 
WEIGHT — unrelated to RVEA's reference VECTORS v₁..v_H, despite the shared letter.)
5.  Rank by Qᵢ ascending; check 'acceptable advantage' Q(2nd)−Q(1st) ≥ 1/(m−1) — if it fails, 
propose a compromise SET instead of a single winner.
Dimension handling: Like TOPSIS, cost is O(m·k); the acceptability threshold 1/(m−1) depends 
only on m (alternative count), never on k.

MGDA: Concept & Generalized Steps
Full form: Multiple-Gradient Descent Algorithm
Proposed by: Désidéri (2012)
Core idea
• For differentiable objectives, find the minimum-norm point in the convex 
hull of the per-objective gradients — the resulting direction weakly 
decreases every objective at once.
Pros / Cons / When to use
•
 Efficient for differentiable objectives; no population needed.
•
 Requires gradients (differentiability); can get stuck at Pareto-STATIONARY 
points that aren't globally optimal.
• Best used when: Deep-learning-style multi-task optimization with a shared 
parameter vector.
• Parameters: Learning rate η.
Generalized steps (any n variables, k objectives)
1.  At current point x∈Rⁿ, compute ∇fᵢ(x)∈Rⁿ for every one of the k objectives (differentiability 
is MGDA's core requirement, unlike the EA methods above).
2.  Find the minimum-norm point in the convex hull of {∇f1(x),…,∇fk(x)}. Writing gᵢ := ∇fᵢ(x) as 
shorthand, for k=2 this has closed form α*=clip[(g2−g1)·g2/‖g1−g2‖², 0,1], d*=α*g1+(1−α*)g2 
(k>2 needs a small QP). Note: this α* is a SOLVED OUTPUT (the optimal mixing weight), unlike 
RVEA's or GradNorm's α, which are fixed input hyperparameters — see the Notation Guide.
3.  If ‖d*‖≈0, x is already Pareto-stationary (no direction improves one objective without 
harming another) — stop.
4.  Otherwise update x ← x − η·d* (weakly decreases every objective simultaneously) and 
repeat.
Dimension handling: Cost per step is O(n·k) for gradients plus a small O(k²) QP for α —
INDEPENDENT of how large n is, which is why MGDA scales to deep nets with millions of shared 
parameters, unlike population methods.

GradNorm: Concept & Generalized Steps
Full form: Gradient Normalization for Adaptive Loss Balancing
Proposed by: Chen, Badrinarayanan, Lee & Rabinovich (2018)
Core idea
• Dynamically re-weight per-task losses in multi-task learning so every task's 
gradient norm at the shared layer trains at a comparable, self-correcting 
rate.
Pros / Cons / When to use
•
 Balances multi-task training automatically; adapts over the whole run.
•
 Needs tuning (α, learning rate); adds a second, small optimization loop on 
top of the main one.
• Best used when: Multi-task learning with a shared backbone and several loss 
heads.
• Parameters: Asymmetry α; loss-weight learning rate.
Generalized steps (any n variables, k objectives)
1.  Maintain one trainable weight wᵢ per task loss (init to 1); the shared parameters θ 
(possibly millions of them) are never enumerated directly.
2.  After each pass, measure gradient norm Gᵢ(t)=‖∇θ(wᵢ·Lᵢ(t))‖ and loss ratio Lᵢ(t)/Lᵢ(0) per 
task.
3.  Compute average gradient norm Ḡ(t) and relative inverse training rate rᵢ(t) = [Lᵢ(t)/Lᵢ(0)] / 
mean_j[Lⱼ(t)/Lⱼ(0)] — a slower-than-average task gets rᵢ>1. (This rᵢ is unrelated to the 
reference POINT r used earlier in SMS-EMOA/HypE — same letter, a training-rate ratio here.)
4.  Target gradient norm for task i: targetᵢ = Ḡ(t)·rᵢ(t)^α. (This targetᵢ is recomputed every step 
from current gradients — unlike Goal Programming's Tᵢ, which is a fixed DM-supplied 
number.)
5.  GradNorm loss Lgrad=Σᵢ|Gᵢ(t)−targetᵢ|; gradient-descend ONLY the wᵢ against this loss, 
then renormalize Σwᵢ=k.
Dimension handling: This whole procedure runs on k scalars wᵢ, never on the n (possibly 
millions of) shared parameters directly — n enters only via the single already-computed scalar 
Gᵢ(t) per task.

Hypervolume (HV): Worked Example
Setup
• True Pareto front (ZDT1-style): f2 = 1 − √f1, sampled at f1 = 0, 0.25, 0.5, 
0.75, 1.0.
• Obtained approximation set (5 points, close to but not exactly on the front): 
(0.02,0.87), (0.24,0.55), (0.48,0.31), (0.80,0.20), (0.95,0.08).
• Reference point r = (1.1, 1.1) — worse than every point on both axes.
• HV(true front) = 0.7283 (upper bound for this sample).
• HV(obtained set) = 0.7234.
• HV ratio = 0.7234 / 0.7283 = 0.9933 → the obtained front captures 99.3% 
of the achievable hypervolume.
Reading the number
• HV is the ONLY common metric that needs no reference/true front to 
compute — only the reference point r.
• Higher HV is always better; it rewards convergence (points closer to the 
true front) AND diversity (spread across it) in a single number.
• It is the metric SMS-EMOA and HypE (this deck) directly optimize, which is 
why those two families tend to score best on HV in comparative studies.
• Weakness: computing exact HV is expensive when k is large — exponential 
in the worst case — hence HypE's Monte-Carlo estimate.

Reading This as a Student: Ambiguities Found & Fixed
Q Why does Goal Programming / Lexicographic show only ONE final answer while the EA slides show a table of several?
Fix Clarified above: scalarizing methods (Goal Programming, Lexicographic, and TOPSIS's ranking of a single winner) are designed to return one preferred/compromise solution. Only population-based Pareto methods and VIKOR's compromise SET return several.
Q The formula H = C(k+p−1, p) wasn't defined inline on the original slide — what are k and p? (The original NSGA-III paper writes this same formula with 'M' instead of 'k'.)
Fix Every formula slide in this deck now states its symbols explicitly (k = number of objectives, p = divisions per objective axis), and standardizes on k throughout — see the Notation Guide for the k/M equivalence and other reused symbols.
Q Constants like IBEA's κ=20, MGDA's η=0.1, or GradNorm's α=0.5/lr=0.025 look like arbitrary 'magic numbers'.
Fix Each worked-example slide now states WHY that value was chosen (e.g. κ scaled to the observed ε-range of 0–86 in that problem) instead of leaving it unexplained.
Q Isn't it a mistake that a dominated design (e.g. D3 under RVEA, D2 under HypE) survives into the final table?
Fix Not a mistake — re-verified against each algorithm's actual selection rule and explicitly flagged as a property of decomposition-/estimation-based selection, with a one-line explanation on that slide rather than silently 'fixing' it away.
Q TOPSIS and VIKOR gave different runner-up rankings on the same supplier data — is one of them wrong?
Fix Neither is wrong: the rationale text now states plainly that TOPSIS (Euclidean closeness) and VIKOR (utility+regret compromise) optimize different notions of 'best', so mild rank differences between the two are expected.
