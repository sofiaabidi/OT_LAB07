Pareto Dominance & the Pareto Front
FORMAL DEFINITION (MINIMIZATION CONVENTION)
a dominates b  (written a ≺ b)   iff
fᵢ(a) ≤ fᵢ(b)  for every objective i,   AND   fⱼ(a) < fⱼ(b)  for at least one objective j
● If neither a nor b dominates the other, they are non-dominated — both are valid trade-offs.
● Pareto-optimal solution: a feasible solution not dominated by any other feasible solution.
● Pareto front / Pareto-optimal set: the set of every Pareto-optimal solution across the whole search space.
● Archive (used throughout this chapter): an algorithm's evolving approximation of the true Pareto front, built from the best non-dominated solutions found so far — it usually isn't the exact front, 
just the best estimate after N iterations.
WORKED EXAMPLE (MINIMIZE BOTH F₁, F₂)
Pair f₁, f₂ values Verdict
a=(2,8) vs b=(4,5) a better on f₁, b better on f₂ Non-dominated — neither wins both
a=(2,8) vs c=(2,6) c ties on f₁, strictly better on f₂ c dominates a
a=(2,8) vs d=(3,9) a strictly better on BOTH f₁ and f₂ a dominates d
Maximizing an objective instead? Just flip that objective's inequality (≥ / >) — exactly how the NSGA-II, MOGWO, MOABC, MODE, MO-TLBO, MOBA, and MOMA examples later in this chapter work, since each maximizes at least one 
objective.

Handling Constraints in Multiobjective Optimization
DEB'S FEASIBILITY RULES (COMPARING ANY TWO CANDIDATES A, B)
One feasible, one infeasible The feasible solution always wins, regardless of objective values.
Both feasible Compare using ordinary Pareto dominance on f₁, f₂, …
Both infeasible The solution with the smaller total constraint violation wins.
CONSTRAINT VIOLATION (CV)
CV(x) = Σᵢ max(0, gᵢ(x))  +  Σⱼ |hⱼ(x)|
gᵢ(x) ≤ 0 inequality constraints · hⱼ(x) = 0 equality constraints. CV = 0 means fully feasible.
PRACTICAL HANDLING STRATEGIES
● Penalty functions — add a CV-scaled penalty to each objective
● Repair operators — project an infeasible x back onto the feasible region
● Feasibility-first selection — used directly inside Constrained NSGA-II

Crowding Distance: How Diversity Is Measured
WHY IT MATTERS
Every heuristic in this chapter leans on crowding distance to pick archive leaders (MOGWO's αβδ, MOBA's x_best), to choose which individuals get local search (MOMA), or to prune an over-full 
archive — it is the mechanism that keeps the front spread out instead of clumping in one region. Terminology note: NSGA-II calls its non-dominated set a “front”; the swarm/evolutionary 
heuristics call the same idea an “archive” — both mean “the best trade-off solutions found so far.”
FORMULA (PER OBJECTIVE, THEN SUMMED)
d_i = Σₘ [ fₘ(i+1) − fₘ(i−1) ] / [ fₘ_max − fₘ_min ]
Solutions are sorted by each objective m; boundary solutions (smallest/largest) get d_i = ∞ so they are always kept.
WORKED EXAMPLE
Solution f₁ f₂ Crowding distance d
P1 (boundary) 32.0 48.0 ∞ (always kept)
P2 34.0 45.0 1.00
P3 36.0 42.0 0.70  ← smallest
P4 36.8 40.8 1.00
P5 (boundary) 40.0 36.0 ∞ (always kept)
Example calculation for P3 (neighbors P2 and P4): d = (36.8−34.0)/(40.0−32.0) + (45.0−40.8)/(48.0−36.0) = 0.35 + 0.35 = 0.70 — the smallest finite value, so P3 is the most “crowded” point and the first candidate to drop if the 
archive needs to shrink; P2 and P4 are more isolated and stay protected.

Fast Non-Dominated Sorting: Assigning Fronts
THE PROCEDURE EVERY NSGA -II -FAMILY METHOD RUNS EACH GENERATION
1 For every solution p, compute n_p (how many solutions dominate p) and S_p (the set of solutions p dominates).
2 Front 1 = every solution with n_p = 0 (nobody dominates it) — these are the current non-dominated solutions.
3 For each p in Front 1, decrement n_q for every q in S_p; any q that drops to n_q = 0 joins Front 2.
4 Repeat step 3 for Front 2, Front 3, … until every solution is assigned to a front.
WORKED EXAMPLE — PREVIEW OF THE UPCOMING CONSTRAINED NSGA -II SCENARIO
Solution (f₁,f₂) Dominated by n_p Front
B (40,36) — (non-dominated) 0 1
C (32,48) — (non-dominated) 0 1
D (36,42) — (non-dominated) 0 1
F (34,45) — (non-dominated) 0 1
E (38.4,36) B 1 2
Complexity: this procedure runs in O(M·N²) for M objectives and N solutions — the dominant cost of one NSGA-II generation, which is why archive size is usually capped.

Constrained NSGA-II: Modifications to Standard NSGA-II
THREE CHANGES TURN NSGA -II INTO A CONSTRAINED OPTIMIZER
1
Compute constraint violation
CV(x) = Σ max(0, gᵢ(x)) + Σ |hⱼ(x)|  for every individual.
2
Replace crowded-comparison with feasibility-first comparison
Feasible beats infeasible → both feasible: Pareto dominance → both infeasible: lower CV wins.
3
Non-dominated sort only among feasible solutions
Infeasible individuals are ranked strictly below every feasible front by CV.
RESULT
The output is a Pareto front consisting only of feasible solutions — every point on it satisfies all constraints and is non -dominated among feasible candidates.

MOPSO:
Multi-Objective Particle Swarm Optimization
Proposed by Coello Coello & Lechuga (2002)
Swarm Intelligence
CORE IDEA
Extend classical PSO with an external archive of non-dominated solutions; each particle's personal best (pbest) and the swarm's global guide (gbest) are chosen via Pareto 
dominance and archive crowding distance rather than a single fitness value.
v = w·v + c₁r₁(pbest−x) + c₂r₂(gbest−x)
x_new = x + v_new
ADVANTAGES
● + Fast convergence on continuous landscapes
● + Simple velocity/position update rule
● + Archive preserves front diversity
DISADVANTAGES
● – Prone to premature convergence
● – Sensitive to w, c₁, c₂ settings
Best used when: Continuous decision variables; Fast, good-enough results needed    Avoid when: 
Highly discrete / combinatorial problems
Parameters: w = 0.7,  c₁ = c₂ = 1.5  (r₁ = r₂ = 0.5 fixed for this example)     |     Complexity: O(kN) per iteration

MOGWO:
Multi-Objective Grey Wolf Optimizer
Proposed by Mirjalili, Saremi, Mirjalili & Coelho (2016)
Swarm Intelligence
CORE IDEA
Extend GWO with an archive: the three pack leaders α, β, δ are re-selected each iteration from the archive by crowding distance (not single-objective rank), and every 
omega wolf moves toward their average.
X_new = (X_α + X_β + X_δ) / 3
ADVANTAGES
● + Very few control parameters
● + Fast convergence
● + Archive-based diversity maintenance
DISADVANTAGES
● – Can converge prematurely on multimodal fronts
Best used when: Continuous MOO with smooth landscapes    Avoid when: 
Highly multimodal problems
Parameters: Leaders re-selected by crowding distance each iteration; archive size     |     Complexity: O(kN) per iteration

T_{k+1} = α·T_k

● + Escapes local optima well

● – Slow convergence
● – Cooling schedule needs careful tuning

Proposed by Xue, Sanderson & Graves (2003)
Evolutionary
CORE IDEA

MOBA:
Multi-Objective Bat Algorithm
Proposed by Yang (2011), extended to MOO
Swarm Intelligence
CORE IDEA
Each bat's frequency-driven velocity is pulled toward (or, for diversity, away from) a crowding-selected archive best. Loudness decays over time, shifting the swarm from 
exploration to exploitation. (The full algorithm also raises each bat's pulse-emission rate r toward 1 in step with the loudness decay, biasing later iterations toward small 
local moves near the best solutions — this walkthrough tracks only loudness A since r doesn't change which points enter the archive.)
fᵢ = f_min + (f_max−f_min)β
v = v + (x_best − x)·fᵢ;  x_new = x + v
A_{t+1} = α·A_t

● + Good exploration–exploitation balance
● + Fast
DISADVANTAGES
● – Sensitive to frequency range and loudness decay rate
Best used when: Continuous MOO    Avoid when: 
Discrete problems

Key Takeaways — Part 4
Constraint Handling: Deb's feasibility rules: feasible beats infeasible; both feasible → 
Pareto dominance; both infeasible → lower CV wins.
Constrained NSGA-II: Feasibility-first crowded comparison; non-dominated sorting runs 
only among feasible solutions.
MOPSO: Archive-guided pbest / gbest steer particle velocity toward the trade-off curve.
MOGWO: α, β, δ leaders are re-selected from the archive each round; omega wolves 
encircle their average.
MOABC: Employed / onlooker / scout bees combine greedy dominance with diversity-
seeking exploration.
MOACO: Two pheromone matrices reward non-dominated routes and let dominated 
ones evaporate away.
MOSA: Non-dominated neighbors are always accepted; dominated ones face a 
Boltzmann acceptance test.
MODE: Mutation + crossover generate trials that replace a target only when they 
dominate it.
MO-TLBO: A crowding-selected "teacher" and a shrinking teaching factor pull the class 
toward the front.
MOBA: Frequency-driven velocity exploits toward the best region while loudness decay 
shifts the balance.
MOMA: NSGA-II global search plus hill-climbing local search sharpens the final front.

E V A L U A T I N G  R E S U L T S
Performance Metrics for MOEAs
Hypervolume (HV) The volume of objective space dominated by the archive, bounded by a reference point. Higher is better — it rewards both 
convergence and spread simultaneously.
Inverted Generational Distance (IGD) Average distance from points on the true Pareto front to the nearest point in the obtained archive. Lower is better; needs a 
known/approximated true front.
Generational Distance (GD) Average distance from the obtained archive to the nearest point on the true front — measures convergence only, not spread.
Spacing / Spread Measures how evenly distributed the archive's points are. Lower spacing = more uniform coverage of the trade-off curve.
Worked hypervolume example (minimize both): archive points A=(6,50) and B=(10,30); reference point r=(12,60) chosen worse than every archive point.
HV = area dominated by A up to r, plus area dominated by B up to r, minus their overlap = (12−6)×(60−50) + (12−10)×(60−30) − (12−10)×(60−50) = 60 + 60 − 20 = 100. A larger HV means the archive dominates more of 
the objective space — exactly why it rewards both convergence and spread together.

D E B U G G I N G  C H E C K L I S T
Common Pitfalls in Constrained MOEAs
1
Comparing objectives on different scales — Normalize objectives before computing crowding distance or hypervolume, or one objective will dominate diversity decisions.
2
Archive growing without bound — Cap archive size and prune by crowding distance each iteration — an unbounded archive slows every later generation.
3 Treating a slightly-infeasible solution as “close enough” — Deb's rules are strict: any CV > 0 loses to any feasible solution, by design — soft constraints need penalty terms 
instead.
4
Declaring convergence too early — Track hypervolume or IGD over generations; a flat front for a handful of generations does not guarantee global convergence.
5 Using one algorithm for every problem shape — Match the heuristic to the search space (see the decision guide) — no single MOEA dominates on every problem (No-Free-
Lunch).

Apply Deb's Feasibility Rules
QUESTION
Given g(x): x₁+x₂ ≤ 60. Compare three candidates using Deb's rules: A(x ₁=25,x₂=40, f₁=50,f₂=30), B(x₁=20,x₂=30, f₁=45,f₂=35), C(x₁=15,x₂=25, f₁=40,f₂=32). Both 
objectives are to be maximized. Which solution(s) belong on the feasible Pareto front?
GUIDED SOLUTION
● Step 1 — CV: A: 25+40=65>60 → CV=5 (infeasible). B: 20+30=50≤60 → CV=0. C: 15+25=40≤60 → CV=0.
● Step 2 — By Deb's rules, A is infeasible so it loses to both B and C automatically, regardless of its objective values.
● Step 3 — Compare B(45,35) vs C(40,32): B has both f₁ and f₂ higher → B dominates C.
● Answer: the feasible Pareto front is {B} only — C is feasible but dominated, and A is discarded as infeasible.

Trace One MOPSO Velocity Update
QUESTION
A particle is at x=8 with v=2. Its pbest is at x=5 and the swarm's gbest is at x=14. Using w=0.6, c₁r₁=0.8, c₂r₂=0.5, compute the new velocity and new position.
GUIDED SOLUTION
● v_new = w·v + c₁r₁(pbest−x) + c₂r₂(gbest−x)
● v_new = 0.6×2 + 0.8×(5−8) + 0.5×(14−8)
● v_new = 1.2 + 0.8×(−3) + 0.5×6 = 1.2 − 2.4 + 3.0 = 1.8
● x_new = x + v_new = 8 + 1.8 = 9.8
● Answer: v_new = 1.8, x_new = 9.8 — the pull toward gbest (+3.0) outweighs the pull toward pbest (−2.4), so the particle moves toward the swarm's better region.

Check Dominance for DE Selection
QUESTION
A DE target is X=(size=10, gain=5.0) [size minimize, gain maximize]. Its trial vector evaluates to U=(size= 9, gain=5.2). Should MODE replace the target with the

● Case 2 — U=(9, 4.8): size 9<10 (better) but gain 4.8<5.0 (worse) → neither dominates the other → non-dominated — keep the target X and add U to the archive instead.
● Takeaway: MODE only overwrites a target when the trial wins on every objective; a genuine trade-off point is preserved, not discarded.

Q&A
Frequently Asked Questions
Q: Why use an archive instead of just the population?
A: The population size is fixed, but the true Pareto front can have far more points than fit in one generation — the archive accumulates the best ones found across all iterations.
Q: Does a bigger archive always mean a better result?
A: No. An unbounded archive can include redundant, closely-clustered points; crowding-distance pruning keeps it both diverse and a manageable size.
Q: Can these algorithms guarantee the true Pareto front?
A: No metaheuristic guarantees global optimality. They provide good approximations; hypervolume/IGD against a known front (when available) is how you judge quality.
Q: Which algorithm should I try first?
A: Constrained NSGA-II — it's the most widely validated, has the fewest surprises, and works as a solid baseline before trying aspecialized heuristic.
